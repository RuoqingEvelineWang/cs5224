# MidMeet
## Introduction
This repo consists of a skeleton for the following:
 - frontend: Uses react, vite and Amazon Amplify (connected to Cognito). Has a default sign up/log in page and homepage.
    - code generated by npm create vite@latest
    - sample code in `App.js`, `CreateEvent.js` and `EventList.js` generated by AI
 - backend: Uses AWS CDK (abstraction layer in typescript instead of using YAML), CloudFormation (automated management of AWS resources), DynamoDB (NoSQL key value store), Lambda (serverless functions), API Gateway
    - code in /cdk generated by init: cdk init app --language typescript
    - infrastructure code in /cdk/lib/cdk-stack.ts defines Cognito, API Gateway, Lambda, and DynamoDB tables for both dev/prod stages
    - sample code in /lambda/index.js generated by AI

## Node/npm version and dependency policy
To keep the frontend dependency tree consistent across team members:
- Commit both `package.json` and `package-lock.json` to Git.
- Do **not** commit `node_modules`.
- When only installing existing dependencies, use `npm ci` instead of `npm install`.
- Only run `npm install <package-name>` when you intentionally add/update a dependency, and commit both `package.json` and `package-lock.json` together.
- Team members should use the same Node.js and npm versions. If this repo includes `.nvmrc`, run `nvm use` before installing dependencies.

## Backend environments and deployment model
The backend CDK stack now supports two deployment stages:
- `dev`
- `prod`

The stage is passed through CDK context using `-c stage=...`.

Examples:
- `npx cdk deploy -c stage=dev`
- `npx cdk deploy -c stage=prod`

If no stage is provided, `cdk-stack.ts` defaults to `dev`.

### What the stage changes
- DynamoDB table names are prefixed by stage, for example:
  - `midmeet-dev-users`
  - `midmeet-prod-users`
- Lambda receives `STAGE` and table names through environment variables.
- DynamoDB removal policy differs by stage:
  - `dev`: `DESTROY`
  - `prod`: `RETAIN`

### Team workflow recommendation
- Use `dev` for daily development and testing.
- Use `prod` only for stable/demo-ready deployment.
- Prefer deploying to the shared team AWS account instead of each member deploying separate personal environments.


## Initial setup steps
1. Clone the git repo.
2. Run the following commands to set up AWS:
   - `brew install awscli`, 
   - `npm install -g aws-cdk`
   - `aws configure` (will ask for access key, which can be set up on aws console: Security credentials - create access key)
3. Run the following command inside **/backend/cdk** folder to bootstrap CDK in your AWS account/region:
   - `npx cdk bootstrap aws://[accountID]/[region]`
4. Run the following command inside **/backend/cdk** to deploy the backend:
   - dev: `npx cdk deploy -c stage=dev`
   - prod: `npx cdk deploy -c stage=prod`
5. After deployment, CDK outputs values such as `UserPoolId`, `UserPoolClientId`, and `ApiUrl`. Copy the required values into the frontend `.env` file for authentication and API access.
6. Run the following command inside **/frontend** to install dependencies strictly according to `package-lock.json`:
   - `npm ci`
7. Run the following command inside **/frontend** to start front end and get url:
   - `npm run dev`

## Development steps
1. If backend code is updated, redeploy the correct stage from **/backend/cdk**:
   - `npx cdk deploy -c stage=dev` for the shared development environment
   - `npx cdk deploy -c stage=prod` for the production/demo environment
   Some infrastructure changes may require recreating resources.
2. If you update `backend/cdk/lib/cdk-stack.ts`, mention in your PR whether the change affects:
   - DynamoDB table names or indexes
   - Lambda environment variables
   - Cognito outputs used by the frontend
   - API Gateway endpoints
3. If frontend code is updated, the React dev server will refresh automatically.
4. If you pull new changes and `package-lock.json` has changed, run `npm ci` again inside **/frontend**.
5. If you intentionally add or upgrade frontend dependencies, use `npm install <package-name>` inside **/frontend**, then commit both `package.json` and `package-lock.json`.
